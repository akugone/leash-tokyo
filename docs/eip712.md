# Leash EIP-712 swap intent

Every swap through a Leash gated pool carries a `SwapIntent` signed by the agent key that the agent's ENS name
points to. This document is the wire contract between `src/libraries/LeashIntentLib.sol` (what the hook
verifies) and `agent/src/intent.ts` (what the bot signs). The two are pinned together by the conformance vector
in `test/fixtures/intent.json`, see the last section.

Type string, hashed into `LeashIntentLib.SWAP_INTENT_TYPEHASH`:

```
SwapIntent(bytes32 node,bytes32 poolId,bool zeroForOne,int256 amountSpecified,uint256 nonce,uint256 deadline)
```

`chainId` is `block.chainid` at verification time, so an intent signed for Sepolia is invalid on an anvil fork
that uses a different chain id. `verifyingContract` is the deployed `LeashHook`, exposed as
`DOMAIN_SEPARATOR()` for debugging.

## Fields

| Field | Meaning |
| --- | --- |
| `node` | ENS namehash of the agent name, e.g. `namehash("trader-1.leash.eth")`. The hook recomputes it from the `label` in `hookData` and its `PARENT_NODE`, and rejects a mismatch with `NodeMismatch`. |
| `poolId` | `PoolKey.toId()` of the pool being swapped. Must equal the pool the hook is called for (`IntentMismatch`). |
| `zeroForOne` | Swap direction, must equal `SwapParams.zeroForOne` (`IntentMismatch`). |
| `amountSpecified` | Must equal `SwapParams.amountSpecified` (`IntentMismatch`). Negative means exact input, positive exact output, Uniswap v4 convention. The bot always uses exact input of the quote token, so the value is negative. |
| `nonce` | Per name replay counter, see below. |
| `deadline` | Unix seconds. The intent is valid while `deadline >= block.timestamp` (`IntentExpired`). |

### Nonce semantics

- The hook keeps `nonces[node]`, readable through `nonces(bytes32)`.
- An intent is accepted only when `intent.nonce == nonces[node]`, otherwise `BadNonce(node, expected, actual)`.
- On acceptance the hook increments `nonces[node]`, so a signed intent can be used at most once. The
  increment lives in the swap transaction: if that transaction reverts for any reason the nonce is untouched
  and the intent stays spendable. Only a successful swap consumes it.
- The counter is per `node`, not per signer. Rotating the `addr` record does not reset it.
- Sign intents strictly in order and never sign two intents with the same nonce.

### Deadline semantics

- `deadline` bounds how long a signed intent can sit in a mempool or a relayer queue. The bot uses
  `now + 300` seconds.
- Comparison is inclusive: a block whose timestamp equals `deadline` still accepts the intent.
- The deadline is checked before the nonce, so an expired intent does not burn a nonce.

## hookData ABI layout

`hookData = abi.encode(string label, SwapIntent intent, bytes signature)`, decoded in Solidity with
`abi.decode(hookData, (string, SwapIntent, bytes))`. `SwapIntent` has only static fields, so the tuple is
inlined in the head. Word offsets:

| Word | Content |
| --- | --- |
| 0 | offset of `label` bytes, always `0x100` |
| 1 | `intent.node` |
| 2 | `intent.poolId` |
| 3 | `intent.zeroForOne` (`0` or `1`) |
| 4 | `intent.amountSpecified` (two's complement int256) |
| 5 | `intent.nonce` |
| 6 | `intent.deadline` |
| 7 | offset of `signature` bytes, `0x140` |
| 8.. | `label` length, then label bytes right padded to 32 |
| .. | `signature` length (65), then `r || s || v` right padded to 32 |

`signature` is the 65 byte `r || s || v` form with `v` in `{27, 28}`. The hook verifies it with OpenZeppelin
`ECDSA.recover`, which rejects high `s` values and any other length.

In viem the same layout is produced by:

```ts
encodeAbiParameters(
  [
    { name: "label", type: "string" },
    { name: "intent", type: "tuple", components: [
      { name: "node", type: "bytes32" }, { name: "poolId", type: "bytes32" }, { name: "zeroForOne", type: "bool" },
      { name: "amountSpecified", type: "int256" }, { name: "nonce", type: "uint256" }, { name: "deadline", type: "uint256" },
    ] },
    { name: "signature", type: "bytes" },
  ],
  [label, intent, signature],
);
```

## viem snippet

```ts
import { createPublicClient, http, keccak256, toHex } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { sepolia } from "viem/chains";
import { encodeHookData, leashDomain, namehash, signIntent } from "../agent/src/intent";
import { LEASH_HOOK_ABI } from "../agent/src/abi";

const account = privateKeyToAccount(process.env.AGENT_PK as `0x${string}`);
const client = createPublicClient({ chain: sepolia, transport: http() });
const hook = "0x<LeashHook>";
const node = namehash("trader-1.leash.eth");

const nonce = await client.readContract({ address: hook, abi: LEASH_HOOK_ABI, functionName: "nonces", args: [node] });
const intent = {
  node,
  poolId: "0x<PoolId>",
  zeroForOne: true,
  amountSpecified: -1_000_000n, // exact input of 1 USDC (6 decimals)
  nonce,
  deadline: BigInt(Math.floor(Date.now() / 1000) + 300),
};
const signature = await signIntent(account, leashDomain(sepolia.id, hook), intent);
const hookData = encodeHookData("trader-1", intent, signature);
// pass hookData as the last argument of PoolSwapTest.swap(key, params, testSettings, hookData)
```

`signIntent` is a thin wrapper over `account.signTypedData({ domain, types: SWAP_INTENT_TYPES,
primaryType: "SwapIntent", message: intent })`.

## Conformance vector

`test/fixtures/intent.json` is generated by `agent/scripts/gen-fixture.ts` with anvil key #0, chain id
11155111, verifying contract `0x1000000000000000000000000000000000000001` and the message shown above. It
records the domain separator, struct hash, digest, signature and the full `hookData`.

`test/LeashIntentFixture.t.sol` reads it with `vm.readFile`, pins `vm.chainId(11155111)` and asserts that
`LeashIntentLib.domainSeparator`, `hashIntent`, `digest`, `encodeHookData` and `decodeHookData` agree with
viem byte for byte, that `ECDSA.recover` yields the fixture signer, and that `vm.sign` on the same digest
reproduces the viem signature. `agent/src/bot.test.ts` checks the TypeScript side against the same file.

Any change to the struct, the domain, or the hookData layout must regenerate the fixture and keep both test
suites green:

```bash
cd agent && bun run scripts/gen-fixture.ts && bun test
cd .. && forge test --match-path test/LeashIntentFixture.t.sol -vvv
```
